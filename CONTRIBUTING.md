# Working together

Read the [short workflow guide](docs/working-together.md).

1. Discuss the brand in issue #2, the pages in #4, and the checklist in #6.
2. Update the plan after discussion. The owner or instructor explicitly approves the version discussed before coding starts.
3. Build one feature at a time. Link its task issue to the checklist, and its pull request to the issue.
4. Record what you checked and update the results table in docs/build-checklist.md.

For documentation changes, run `npm run docs:build`. Keep wording approachable for students new to GitHub. No separate decision log, review queue, or commit-hash approval form is needed. Keep a link to the reviewed version in the discussion so approval remains clear.
