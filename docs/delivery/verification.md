## Documentation release checks
- Metadata check and production build pass.
- Every specification appears in navigation, search, and the review queue.
- Review discussion links point to the matching GitHub issue.
- Repository edit links use the correct branch and file.
- A nested page loads directly under the GitHub Pages project path.
- Read navigation and review controls on desktop and a narrow viewport; check keyboard focus.
- Check the published Pages deployment, not just the local server.

## Storefront verification plan
No storefront tests have run because the storefront has not been built. Implement meaningful checks for CART-01, CART-02, CHECKOUT-01, SEO-01, and A11Y-01 after their specifications are approved.

For each requirement record the tested commit, procedure or automated test, expected outcome, actual result, and evidence. Include invalid input, empty states, unavailable storage, direct page entry, keyboard use, and mobile layouts.

## Release checklist
Confirm all scoped requirements are approved and verified, product claims have evidence, sample content is labeled, demo checkout cannot take payment, deployment paths work, and no unresolved blocker remains.
